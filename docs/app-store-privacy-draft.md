# App Store Privacy（Appのプライバシー）回答ドラフト

このドキュメントは、App Store ConnectのApp Privacy（Appのプライバシー）質問票に回答するための**社内検討用ドラフト**です。
実装（コード・DBスキーマ）を根拠に、Appleのデータ分類ごとに「収集の有無」「ユーザーへのリンク」「トラッキング利用」「利用目的」「根拠」「不確実性」を整理しています。

**注意**:
- 本ドキュメントは実装を変更せず、既存の調査結果を整理したものです。
- 最終的なApp Store Connect上の回答は、この内容をベースに人が確認・確定してください（本ドキュメント自体はApp Store Connectへの登録作業ではありません）。
- Appleのデータ分類定義は随時更新されるため、回答直前に[Apple公式のガイドライン](https://developer.apple.com/app-store/app-privacy-details/)と突き合わせてください。
- 「〇〇だから申告不要」といった断定は避け、判断理由を残す方針で記載しています。

## 前提: Apple Sign inの必須申告事項

Apple Sign inを実装している場合、App Store Connect側で「Sign in with Apple」に関する追加の申告（Appleが要求するプライバシー関連の必須対応）があります。これは本ドキュメントの範囲外のため、別途App Store Connectのガイドに従って確認してください。

## データ種別ごとの整理

### Name（氏名）

| 項目 | 内容 |
|---|---|
| 収集 | あり |
| ユーザーにリンクされるか | される（アカウントに紐付け） |
| トラッキング目的での利用 | 無し |
| 利用目的 | アプリの機能（マイページの表示名表示） |
| 根拠 | `apps/mobile/lib/authActions.ts`（Apple `fullName`から`displayName`を構築）、Turso `users.display_name` |
| 不確実性 | Appleは初回認可時のみ氏名を返す仕様であり、以降はキャッシュ値を利用する。「氏名を収集している」という事実自体は変わらないため、収集ありとして扱うのが妥当と考えられる。 |

### Email Address（メールアドレス）

| 項目 | 内容 |
|---|---|
| 収集 | あり |
| ユーザーにリンクされるか | される |
| トラッキング目的での利用 | 無し |
| 利用目的 | アカウント認証、アカウント管理 |
| 根拠 | Turso `users.email`, `users.email_is_private_relay` |
| 不確実性 | Appleの「メールを非公開」機能利用時は非公開リレーアドレスが渡されるが、それでも「メールアドレスを収集している」事実に変わりはないため収集ありとする。 |

### User ID（ユーザーID）

| 項目 | 内容 |
|---|---|
| 収集 | あり |
| ユーザーにリンクされるか | される |
| トラッキング目的での利用 | 無し |
| 利用目的 | アプリの機能（アカウント管理、複数端末同期）、認証 |
| 根拠 | Turso `users.public_user_id`（UUIDv4、外部公開用）、`user_identities.provider_user_id`（Apple sub） |
| 不確実性 | 内部整数ID（`users.id`）は外部に一切出力しない設計のため、Appleへの回答上は`public_user_id`のみを対象とすればよいと考えられる。ただし「内部IDも技術的には存在する」ことは記録として残す。 |

### Purchase History（購入履歴）

| 項目 | 内容 |
|---|---|
| 収集 | あり |
| ユーザーにリンクされるか | される |
| トラッキング目的での利用 | 無し |
| 利用目的 | アプリの機能（課金・プレミアム機能の権利管理） |
| 根拠 | Turso `subscription_entitlements`, `revenuecat_events`。RevenueCat経由でのStoreKit購入情報の取得。 |
| 不確実性 | 購入処理自体はApple/StoreKitが行い、CardHubは entitlement状態（有効/無効、商品種別、有効期限等）のみを保持する。「決済情報（カード番号等）」は一切保持しない。Purchase Historyとしての申告要否は該当すると考えられるが、Payment Info（決済手段の詳細）は該当しないと考えられる。 |

### Product Interaction（プロダクトの操作情報）

| 項目 | 内容 |
|---|---|
| 収集 | あり（該当する可能性が高い） |
| ユーザーにリンクされるか | される |
| トラッキング目的での利用 | 無し |
| 利用目的 | アプリの機能（自分の抽選の管理、統計・分析機能） |
| 根拠 | Turso `user_lotteries`, `user_lottery_status_history`, `checklist_progress`, `user_favorites`, `followed_products`。これらはユーザーがアプリ内で行った操作（保存、ステータス変更、チェック等）の記録であり、統計機能（`/me/statistics/*`）の算出元でもある。 |
| 不確実性 | Appleの定義する「Product Interaction」（アプリ内操作の分析目的での利用）に厳密に該当するかは、Appleのガイドライン文言と照らして最終確認が必要。本アプリの場合は分析・広告目的ではなく、ユーザー自身が管理するデータの保存が主目的である点に留意（ただし統計機能の算出には用いている）。 |

### Device ID（デバイスID）

| 項目 | 内容 |
|---|---|
| 収集 | あり |
| ユーザーにリンクされるか | される（`refresh_tokens.device_id`経由でユーザーに紐付く） |
| トラッキング目的での利用 | 無し（他社・他アプリを横断した広告トラッキングには使用しない） |
| 利用目的 | アプリの機能（複数端末の識別、「全端末からログアウト」機能、リフレッシュトークンのローテーション管理） |
| 根拠 | `apps/mobile/lib/deviceId.ts`（アプリ内で生成する乱数UUID、SecureStoreに保存）、Turso `refresh_tokens.device_id` |
| 不確実性 | **「ハードウェア固有IDではなくアプリ生成の乱数だから申告不要」と自動的に判断しない。** Appleの定義する"Device ID"は、IDFA/IDFV等のハードウェア系識別子に限定されず、デバイスを識別するために使われる識別子全般を指しうる。本アプリのdeviceIdはユーザーアカウントに紐付き、機能上デバイスを識別する目的で使用しているため、Device IDとして申告する、または少なくとも「Identifiers」カテゴリの該当性を慎重に検討することを推奨する。最終判断はAppleの最新ガイドラインとの突合が必要。 |

### Other Diagnostic Data（その他の診断情報）

| 項目 | 内容 |
|---|---|
| 収集 | 無し（コード上確認できず） |
| ユーザーにリンクされるか | 該当なし |
| トラッキング目的での利用 | 該当なし |
| 利用目的 | 該当なし |
| 根拠 | モバイルアプリ・バックエンド双方でSentry等のクラッシュレポート/診断SDKの導入なし（`package.json`依存関係・コード全文grepで確認済み）。サーバー側ログはCloudflare Workersの標準console出力のみで、Apple Privacyの申告対象となる「アプリからAppleまたは第三者へ送信される診断データ」には該当しないと考えられる。 |
| 不確実性 | Expo/EAS自体がビルド・配信基盤として何らかの匿名化されたテレメトリを収集している可能性はあるが、これはExpo社のインフラ利用に伴うものであり、CardHubアプリのコードが能動的に収集・送信しているものではない。Expo社自身のプライバシーポリシーの確認が別途必要。 |

### IPアドレスのハッシュ

| 項目 | 内容 |
|---|---|
| 収集 | あり（ハッシュ化した形でのみ） |
| ユーザーにリンクされるか | される可能性あり（`audit_logs.user_id`と紐付くレコードが存在する） |
| トラッキング目的での利用 | 無し |
| 利用目的 | 不正利用防止、レート制限、セキュリティ監査 |
| 根拠 | Turso `audit_logs.ip_hash`（SHA-256、生IPは保存しない） |
| 不確実性 | Appleの分類には「IPアドレス」を独立したデータ種別として明示するケースがある（例: Diagnostics内、または他のカテゴリの一部として）。ハッシュ化していることが「収集していない」ことを意味しない点に留意し、収集ありとして扱うことを推奨する。 |

### RevenueCatが取得する購入情報

| 項目 | 内容 |
|---|---|
| 収集 | あり（CardHub経由ではなくRevenueCat社を通じて） |
| ユーザーにリンクされるか | される（`public_user_id`をApp User IDとして使用） |
| トラッキング目的での利用 | RevenueCat社のサービス仕様に依存するため、CardHub側では「トラッキング目的での利用は指示していない」が、最終的な扱いはRevenueCat社のプライバシーポリシー・データ取扱いに従う |
| 利用目的 | 課金・サブスクリプション管理 |
| 根拠 | `apps/mobile/lib/purchases.ts`, `lib/billingLifecycle.ts`、サーバー`routes/billingWebhook.ts`。送信する識別子は`public_user_id`のみで、メールアドレス・内部整数IDは送信しない。 |
| 不確実性 | App Store Connectの「サードパーティパートナー」に関する申告で、RevenueCatを「データを収集する第三者SDK」として申告する必要があるかを確認する。RevenueCat社自身がAppleに提出しているプライバシー情報（RevenueCat社のSDKとしての標準的な申告内容）も参考にすること。 |

## その他、申告不要と考えられる項目（現時点）

以下は実装上確認できなかったため、収集していないものとして扱う候補です。ただし将来の実装変更時は本ドキュメントの見直しが必要です。

- Health & Fitness（健康情報）
- Location（位置情報）
- Contacts（連絡先）
- Browsing History / Search History
- Advertising Data（広告データ）
- Financial Info（決済手段の詳細。Purchase Historyとは区別）
- Sensitive Info（機微情報）

## 総括と次のアクション

- 上記の中でも特に **Device ID** と **IPアドレスのハッシュ** は、「加工しているから申告不要」と即断せず、Apple最新ガイドラインとの突合を推奨する。
- RevenueCatを含む「サードパーティSDK」の申告要否についても、RevenueCat公式ドキュメントの最新情報を確認すること。
- 最終回答はApp Store Connect上で人が入力し、本ドキュメントはその判断材料として使うこと（本ドキュメント自体が公式回答ではない）。
